## 2. Bugs, reproductions, fixes and negative controls

1. **High: a tunnel bypassed host-only authorization.** `index.js:3060`. Unauthenticated GETs against the supplied URL returned `/` ? 401, `/llm-cli/usage.json` ? 200, `/llm-cli/setup.json` ? 200 with `actionTokenPresent=true`. No administrative action was executed through the tunnel, and the token value is omitted from this report and saved evidence. Root cause: only the upstream socket address was checked, so a local reverse proxy became a privileged local user. Fix: forwarded/Cloudflare headers and a non-local Host remove the loopback exemption. Remote reads require the configured read token; setup/update remain unavailable through proxies. `request-origin.test.mjs` failed before the fix: expected 403, actual 200. It now passes for forwarded, X-Forwarded-For, Cloudflare, foreign Host and subdomain lookalikes, including administrative POSTs with an otherwise valid action token. Reverting the forwarded-header guard in a scratch copy fails the suite. **The running tunnel has not loaded this fix.**

2. **Malformed authentication cookies could throw instead of returning 403.** `index.js:3091`. Repro: remote request with `Cookie: llm_cli_token=%ZZ` and a configured dashboard token. Root cause: unguarded `decodeURIComponent`. The fix treats invalid encoding as an invalid token. The origin suite now verifies 403. Reverting just this catch in a scratch copy exits 1 with `URIError: URI malformed`; [negative control](export/audit-20261017/cookie-mutation.log).

3. **Daily token stacks overcounted Grok and Codex.** `client.js:581` and `client.js:603` (daily chart projections). Repro fixture: input=100 including cache=40, output=20 including reasoning=5. Native total=120; old stacked total=165. Root cause: raw input plus cache plus output plus reasoning were all added. Fix: display uncached input, output and cache; reasoning remains inside output. Corrected the token-mix explanatory text as well. New client assertion failed with `expected: 120 / actual: 165`, then passed. Reverting chart input normalization in a scratch copy fails it. Both daily charts are checked. [Before](export/audit-20261017/chart-before.log), [mutation results](export/audit-20261017/mutations-final.log).

4. **A setup status could remain signed out after a successful later refresh.** `client.js:507`. Repro: earlier setup action leaves `auth.codex.signedIn=false`; a new usage response has `routes.codex.signedIn=true`. Rendering preferred the old action state indefinitely. Fix: successful usage responses reconcile existing setup state with the new host snapshot and clear completed login instructions. New effect-execution test failed with `expected: true / actual: false`; it passes now and fails when reconciliation is reverted. [Before](export/audit-20261017/auth-stale-before.log).

5. **Setup conflated optional/unknown sign-in with signed out.** `client.js:829`. Root cause: the setup panel used a truthy/falsy label even though route cards already knew about optional/null states. OpenCode free models can work while its paid-account sign-in is absent. Fix: explicit optional/unknown labels and a `Sign in for paid models` action. Fixture tests cover optional false and null; reverting the optional label fails the client suite. This does not assert that a paid model is available without authentication. On this run, real local and tunnel JSON reported all three routes signed in; the user's exact historical screen was not observed.

6. **The mobile toolbar overflowed.** `client.js:620`. Browser repro: viewport=390, document width=397. Root cause: the toolbar's inline flex group did not wrap. Adding wrapping produced 390/390. The final browser check asserts no horizontal document overflow at that width. This has executed browser coverage, not a standalone npm-suite assertion. [Browser results](export/audit-20261017/visual-final.json), [mobile screenshot](export/audit-20261017/08-react-mobile-final.png).

7. **Dashboard source explanation contradicted working model discovery.** `index.js:3214`. It said OpenCode exposed no model context/output metadata while the live catalog probe returned 25 models and limits. Updated it to name `opencode api GET /api/model` and label the unavailable-catalog fallback. This is validated by source review and the live catalog output; there is no dedicated mutation test for this sentence.

8. **Unresolved: real OpenCode vision returned the wrong color.** `defaultRoutes().opencode.buildArgs`, `index.js:123`. `node test/_audit.mjs real-capabilities` used the generated red PNG through the real attachment service seam and CLI file flag. Codex and Grok returned `Red`; OpenCode's default model returned `Green.`. Stub tests verify exact image bytes and cleanup; they do not prove model vision. Root cause is **unverified** between CLI/model interpretation and provider behavior. No transport change or test weakening was made to hide the failed result.

Other observed limitation: real OpenCode v2.0.32 emitted only a text event for a successful minimal reply, without `step_finish` or usage/cost events. Its adapter therefore produced no usage chunk for that turn. The independently queried `opencode stats` still supplied dashboard history. No per-turn token count or price was invented. Grok and Codex emitted real usage chunks; Codex's sample satisfied `1857 + 12544 + 7 = 14408` across uncached input, cached input and output. Real legacy `codex exec --json` emitted top-level `turn.completed.usage`, resolving the earlier uncertainty for this installed release; arbitrary older releases remain unverified.
